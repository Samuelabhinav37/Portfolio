<Dropcap letter="B">efore the world was wired together, sharing a file meant walking it across a room. To hand someone a spreadsheet, a new game, or a document in 1986, you saved it onto a physical floppy disk, put on your shoes, and carried it there yourself.</Dropcap>

```text
[ PC A ] ---> Save to Floppy Disk ---> [ Walk across room ] ---> Insert into [ PC B ]
```

People called it sneaker-net, and because these machines had no network cable running anywhere, their owners assumed they were untouchable. Air-gapped meant safe, or so the thinking went. Malicious code didn't need a wire. It just needed a host willing to carry it.

## The biology of code

Computer scientist Fred Cohen formally coined the term "computer virus" in 1983, borrowing the concept straight from biology: a piece of parasitic software that attaches itself to legitimate code and relies on human action to replicate and spread to new hosts.

<Mnote sub="the same Adleman from two posts ago" />Cohen's own doctoral advisor suggested the name. Leonard Adleman, the A in RSA, was the one who first called this new category of self-replicating code a virus.

```text
                   BIOLOGICAL VS. DIGITAL VIRUSES
Biological Virus:   RNA / DNA Payload   ---> Hijacks Host Cell ---> Spreads via Sneezes
Computer Virus:     Machine Bytecode    ---> Hijacks System RAM ---> Spreads via Floppy
```

A pure virus can't spread on its own across an idle network the way a worm can, a different category with its own story. It needs an unsuspecting user to physically carry the media and run the infected file themselves.

## The boot sector hijack: Brain (1986)

<Mnote sub="Apple II, four years earlier" />Brain wasn't actually the first self-replicating floppy virus. Richard Skrenta's Elk Cloner had already pulled off the same trick on the Apple II in 1982, hijacking that platform's own boot sector four years before Brain existed.

In 1986, two brothers in Lahore, Pakistan, Basit and Amjad Farooq Alvi, wrote Brain, widely recognized as the first virus for MS-DOS PCs specifically. Brain didn't hide inside an ordinary document or program. It went straight for the most privileged real estate on the disk: sector zero, the boot sector, code a machine trusts and runs before an operating system ever gets a say.

```text
STANDARD BOOT SEQUENCE:
[ Turn on PC ] ---> [ Read Floppy Sector 0 (Bootloader) ] ---> [ Launch DOS OS ]

BRAIN VIRUS HIJACK:
[ Turn on PC ] ---> [ Read Sector 0: Brain Malware ] ---> [ Load Brain into RAM ]
                                                                 |
                                              [ Relocate Real Bootloader to Sector 7 ]
                                                                 |
                                              [ Hide in RAM & Monitor All Disk Drives ]
```

1. **The trap**: you insert an infected floppy disk and boot the PC.
2. **Memory residency**: Brain runs before DOS even loads, copying itself into the highest addresses of system RAM.
3. **The intercept**: Brain hooks the BIOS's standard disk-read interrupt, INT 13h.
4. **The spread**: insert any clean floppy to save your work, and Brain silently copies its bytecode into that disk's boot sector too.
5. **Stealth**: point a diagnostic tool at sector zero, and Brain redirects the view to the clean boot code it relocated to sector seven, hiding its own presence.

<span class="highlight">Perimeter defenses mean nothing once the threat rides in on media you trusted enough to insert yourself.</span>

## The first antivirus countermeasures

As boot sector and file-infector viruses like Elk Cloner, Brain, and Jerusalem spread across schools and offices, the industry built its first defensive category, and viruses adapted to beat it almost immediately:

- **Signature matching**: scan disk files for known byte sequences unique to specific malware. Viruses answered with polymorphic code, encrypting themselves and mutating their byte pattern on every new infection so no two copies looked alike.
- **Integrity checksums**: hash a file to catch any change in its size or contents. Viruses answered by hooking the operating system's own file calls and reporting the original, unmodified size back to whatever was asking.

<DetectionOpportunity>Every early antivirus bypass followed the same shape: the virus didn't beat the detection method head-on, it fed the detector a version of reality it already trusted. Any check that relies on the infected system to honestly report its own state is a check malware can lie to.</DetectionOpportunity>

> The boot sector doesn't ask permission. Whatever's sitting there runs first, before anything else gets a vote.

The boot-sector virus proved that code could replicate through nothing but physical proximity and an unsuspecting hand. The next shift wasn't technical at all. It was about malware that stopped hiding somewhere a user would never look, and started disguising itself as something a user would go looking for and download on purpose.
